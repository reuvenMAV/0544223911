# n8n Intent Router + Specialist Agents (OpenRouter)

This implementation gives you a runnable, importable n8n workflow for:

- Input via **Webhook POST** (and easy bridge for Telegram/WhatsApp)
- **Intent classification** (`billing`, `general`, `support`, `service`)
- **Routing** with Switch node
- Specialist agent response generation
- Per-user memory (last 5 interactions)

---

## 1) Data Contract

### Incoming request (Webhook)

`POST /webhook/intent-router`

```json
{
  "user_id": "12345",
  "message": "יש לי בעיה בחיוב"
}
```

### Router output contract (internal)

The router LLM must produce JSON only:

```json
{
  "intent": "billing",
  "confidence": 0.92
}
```

If parsing fails or confidence is below `0.6`, the workflow falls back to `general`.

### Response payload (Webhook response)

```json
{
  "user_id": "12345",
  "intent": "billing",
  "confidence": 0.92,
  "answer": "....",
  "memory": {
    "last_message": "...",
    "last_intent": "...",
    "history": []
  }
}
```

## 2) Required Environment Variables

Set these in n8n environment settings:

- `OPENROUTER_API_KEY` (required)
- `OPENROUTER_MODEL` (optional, default: `openai/gpt-4o-mini`)

OpenRouter endpoint used:

`https://openrouter.ai/api/v1/chat/completions`

---

## 3) Import & Run

1. Open n8n.
2. Import file:
   - `n8n/workflows/intent-router-openrouter.json`
3. Activate workflow.
4. Copy test URL from the **Webhook** node.
5. Send test request:

```bash
curl -X POST "http://localhost:5678/webhook-test/intent-router" \
  -H "Content-Type: application/json" \
  -d '{"user_id":"12345","message":"יש לי בעיה בחיוב"}'
```

Expected:
- `intent` should be `billing` (or `general` if classifier confidence is low).
- `answer` is generated by the routed specialist agent.
- `memory.history` keeps up to 5 latest interactions for that user.

---

## 4) Node Order (as implemented)

1. Webhook
2. Normalize Input (Set)
3. Load Memory (Code, workflow static data)
4. Router Agent (HTTP Request to OpenRouter)
5. Parse Router JSON (Code)
6. Switch Intent
7. Billing Agent / General Agent / Support Agent / Service Agent (HTTP Request)
8. Build Final Answer (Code)
9. Save Memory (Code)
10. Respond (Respond to Webhook)

---

## 5) Telegram / WhatsApp Integration

### Telegram (recommended first)

Add:
- `Telegram Trigger` node
- Map message fields to:
  - `user_id = {{$json.message.from.id}}`
  - `message = {{$json.message.text}}`
- Connect into `Normalize Input` (or directly to `Load Memory` with matching schema).
- After `Build Final Answer`, add `Telegram -> Send Message`.

### WhatsApp (Meta or Twilio)

Use WhatsApp webhook as upstream:
- Receive in n8n Webhook (convert to `user_id`, `message`).
- Reuse this same flow.
- Send answer back with provider API HTTP Request node.

## 7) Notes on Memory

Current implementation stores memory in `workflow static data` under:
- `memoryByUser[user_id]`

Structure:

```json
{
  "last_message": "...",
  "last_intent": "...",
  "history": [
    {
      "user": "...",
      "assistant": "...",
      "intent": "...",
      "timestamp": "..."
    }
  ]
}
```

This is enough for development and small usage. For high scale, move to Redis/Supabase.
